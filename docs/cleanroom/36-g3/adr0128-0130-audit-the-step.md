**What the bar forbids, if none can tell.** This is where I believe the repair actually creates a substantive, byte-level fork rather than a merely notional one. The unmodified paragraph immediately following (hunk 24's home, the "line is drawn" principle) states the bar's entire *purpose*: fixed declarations are exactly the ones that determine how stored bytes are read (§14/§14.5), addressed (§11.4), shaped (§15), and produced (§17, codec/filter) — "Under new ones the same bytes would denote values, coordinates or padding the writer did not store... no check any actor owes able to see it" except for a short, named list of witnessing register rows (T3, T14, T21, T22, T4, T5, T2, T17, T24, T25). **Byte-level verdict (B-01).** Take FILE X: a directory with one layer record L, declared type T2 (say int16), whose sole tile-index entry's (offset, length, crc) is byte-identical to a tile that was correctly encoded and stored under type T1 (say float32) in a strictly earlier generation of the same physical file, that earlier record having been dropped in the same commit that added the T2 record. Under the scope sentence's literal, permissive reading, a conforming appender **may** emit FILE X in one ordinary commit (drop L, add "new" L under §20.4/hunk-23, addressing the old extent). Under the reading implied by the bar's own stated purpose (identical hazard to a forbidden in-place type change; the safety-relevant path for changing a fixed declaration on data that keeps its bytes is the §20.5 rewrite, which is contractually required to decode-then-recreate and therefore would not, in the general case, reproduce those exact raw bytes under that mismatched declaration), **no conforming writer** — appender or rewriter — legitimately produces FILE X. That is a fork in the emittable set over a concrete file, not merely a difference in actor bookkeeping, so I grade this **byte-level**, with the caveat noted (the passage's inherited, unchanged statement "no file is nonconforming by virtue of its violation" means neither reading makes FILE X itself *fail a conformance check if it already exists*; the fork is over whether a conforming *writer* is licensed to *produce* it, which is exactly what the byte-level test asks).
