## Method

1. Parsed both files into sections by markdown heading (`#`..`####`), matched sections between editions by heading text (title), since B reorders §3 ahead of §2 (see below).
2. For each matched section, unwrapped hard-wrapped lines into logical blocks (paragraph / bullet / numbered-item / blockquote / table-row / fenced-code), collapsing whitespace, then diffed the block sequences with `difflib.SequenceMatcher`. This removes re-wrap noise (both editions are hard-wrapped) and leaves only actual content differences.
3. Sections whose block sequence has zero diff ops are content-identical (mod whitespace) between editions; I spot-verified this with raw `diff` on two large control sections (§9.2, the §20 header) and both came back byte-for-byte identical, confirming the pipeline isn't silently matching everything as equal.
4. Of 130 matched section titles, only 7 had any diff: front matter, §1 Introduction, §2.3 Conformance classes, §2.4 Outcome classes and owning scope, §3.1 Terms, §12 (intro prose), §21.6 Conditions that are not violations. This matches the project's own edit log (only these areas have had "Readable:" rewrite commits so far); the other 123 matched sections are untouched between editions, so — since my mandate is "does B decide anything A does not" — they cannot contain an addition and were not re-read line-by-line beyond the automated exact-match check.
5. §3.3 "Container and array model" (A only) has no B counterpart at all: it is a Note-only sub-section (see below); B has zero sections with no A counterpart.
6. Control searches for zero-claims: grepped `R-CNT-24` in both files (10 in A vs 7 in B) and accounted for every one of the 3 missing occurrences — all three sit inside the one Note block dropped from §2.3 (worked reach examples for F14/F5/F15); no other occurrence differs. Grepped `strictly increasing` / `never a delta` (phrases cut from the §3.1 "generation"/"directory" glosses) and confirmed the underlying claims are independently and fully stated, unchanged, in §9.2/§9.3/Appendix D — so those specific cuts are pure de-duplication, not loss of substance.

### §3.1 Terms
- **Reordering.** B moves the "front signature block," "generation," "trailer," "directory" definitions to the front of the list (immediately after §3.1 becomes a whole-document-second section, ahead of §2). "front signature block" and "trailer" are reproduced verbatim. "generation" drops "successive generations of one file are ordered by the strictly increasing committed file length their trailers carry (§9.3)" — confirmed independently and fully stated, unchanged, in §9.3 itself, so no substance lost. "directory" drops "— never a delta (§9.2) — so a conforming commit adds one directory per generation" — confirmed independently stated in §9.2 and Appendix D, unchanged, so no substance lost.
- **dimension.** A: "the declared order is load-bearing (§11.4)" (vague). B: "the declared order fixes the sample order on disk: within a tile the last-declared dimension varies fastest, and tile ordinals follow the same order (§11.4)" (concrete). Checked against §11.4 (unchanged): it does state row-major = last-declared-dimension-varies-fastest for both the in-tile ordinal and (via the same construction) the spatial tile ordinal, and only linearization = 1 (row-major) is emittable by a format-major-1 writer. B's claim is therefore an accurate derivation of A's own text, not a new decision — not reported as an addition.
- **channel.** Same pattern: A's vague "the order is load-bearing (§11.4, §14)" becomes B's concrete "fixes where the channel's value sits within each interleaved sample (§14) and where its tiles fall in a planar layer's index (§11.4)" — checked against §14.1 and §11.4 (both unchanged): matches their content (`c · N + s` planar disk ordinal, sample-major interleaved layout). Grounded, not an addition.
- **channel layout.** B drops the trailing cross-reference clause ("encoded in the layer record (§7.4), byte-layout semantics in §14"); no content change, pure trim.
- **tile.** B inserts a new sentence: "A tile *carries* a channel when its payload holds that channel's samples at the cell's positions." This formalizes a word ("carries") used pervasively and un-defined throughout A (§3.2, §13, §14, the §21.6 table, etc.). Checked §3.2 (unchanged): "If the tile carrying that channel at that coordinate is stored, the channel's value is..." and "one tile carries every channel" (interleaved) / "each channel's storedness is independent" (planar) — B's new definition is a faithful, unambiguous restatement of usage A's own text already fixes everywhere it uses the word. Not reported as an addition (grounded in A's own consistent usage).
- **fill value.** A: "the **per-channel** value that a channel's samples take..."; B drops "per-channel." Checked §13.1 (unchanged): "Every channel entry records a fill value" confirms it is still per-channel via the surrounding "a channel's samples" wording; no scope change.
- **addressed tile / stored tile.** A: "every tile of a layer is *addressed*" — an unconditional, generation-independent statement. B: "a tile is *addressed* **in a generation** if that generation's tile index has an entry for it: the tiles of the layer's grid under the geometry **that generation declares**" — an explicitly generation-relative definition. Checked whether a layer's geometry (grid/extents/tiling) can in fact change across generations per A's own normative text: yes — §20.3 step 4 (unchanged) discusses "a shrink... a re-tiling... a change of rank" as permitted changes requiring specific handling, and in the same step: "a channel removed from the end takes only its own tiles out of the addressed set, and a tile the new state does not address carries no obligation" — i.e., A's own §20.3 already treats "addressed" as varying with "the new state" (the generation), directly in tension with §3.1's flat "every tile of a layer is addressed." B's rewrite resolves this tension by adopting the generation-relative reading, which is grounded in A's own §20.3 text even though it goes beyond the literal words of A's own §3.1 term entry. → **swba-03, AMBIGUITY** (flags both B's silent resolution of a real internal inconsistency in A, and the fact that a reader of A's Terms section alone would not learn that "addressed" is generation-relative).
